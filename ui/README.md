# Фронтенд контроля качества ДРА

Интерфейс сервиса оценки качества укладки DXA-снимков. Два контура, которые
определяются ролью при входе:

- **Пост рентгенолаборанта** — один экран: вердикт по только что сделанному снимку,
  критерии укладки с пояснениями и решение. Снимок либо приходит сам с аппарата, либо
  загружается кнопкой — режим кабинета выбирается при пусконаладке, см. ниже.
- **Центр обработки** — очередь исследований, карточка снимка с разметкой, пакетная
  обработка архива, отчёты, служебный экран.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Прочие команды: `npm run build` (проверка типов + сборка), `npm run lint`, `npm run preview`.

Нужен Node 20+. Если его нет, подойдёт портативная сборка с nodejs.org — ставить
глобально не обязательно.

## Демо-режим

По умолчанию UI работает с `dicom-manager`. Для демо без сервера задайте
`VITE_USE_MOCKS=true` в `.env` и перезапустите Vite (или пересоберите Docker-образ).

Мок — не набор готовых ответов, а **состояние**: свежая установка пустая, загруженный файл
действительно становится задачей, задача проходит `pending → processing → completed`, решение
специалиста сохраняется, отчёт скачивается настоящим CSV. Состояние лежит в `localStorage`, так
что снимок, загруженный на посту, видит центр обработки, а перезагрузка страницы ничего не теряет.

```
src/lib/mockAdapter.ts        маршрутизация: подмена транспорта axios
src/services/mock/store.ts    состояние: задачи, отчёты, стадии обработки
src/services/mock/demoJobs.ts заготовки результатов ML (настоящие ответы qc_prototype)
src/services/mock/zip.ts      имена файлов из архива — читается central directory
src/services/mock/csv.ts      файл отчёта
```

Чего мок не делает: не смотрит в пиксели. Разбор берётся из заготовки по области, а область —
из имени файла (`ПОП` → позвоночник, `ЛПОБ` / `ППОБ` → бедро). Для трёх файлов из
`data/Для теста` геометрия разметки подлинная и совпадает с анатомией.

Снимки одного посещения группируются по префиксу имени файла: `CR000000_ПОП.dcm` и
`CR000000_ППОБ.dcm` — один пациент.

Демо-данные для показа: «Служебное» → «Заполнить демо-данными», там же «Очистить всё».

Два аккаунта — контур определяется ролью, никаких кнопок быстрого входа:

| логин | пароль | куда попадаем |
|---|---|---|
| `ivanova.a.p@example.com` | `laborant2026` | пост рентгенолаборанта, поликлиника № 218 |
| `sokolova.m.i@example.com` | `centr2026` | центр обработки, врач-рентгенолог |

Неверный пароль отвечает `401`, как ответил бы сервер.

**Сервисы в `src/services/` настоящие** — чтобы перейти на живой бекенд, достаточно

```bash
cp .env.example .env
# VITE_USE_MOCKS=false
# VITE_BASE_URL=/api
```

Vite направляет `/api` на `http://localhost:10000`, nginx в Docker — на
`http://dicom-manager:10000`. При другом порте измените адрес upstream в конфигурации
прокси. Прямой `VITE_BASE_URL` требует настройки CORS на стороне сервера.

Вход: `POST /user/login` с `{ email, password }`; ответ содержит `token`, `user_id`,
`organization_id`, `role`. Профиль возвращает один `organization_id`. Одиночный DICOM
передаётся бинарным телом `application/dicom`, ZIP — multipart-полем `file`.

## Контур поста: два режима приёма

Как снимок попадает на экран лаборанта, решается один раз при пусконаладке — в «Настройках
кабинета» (шестерёнка в шапке, `/setup`). Переключателя посреди смены нет: при потоке пациентов
разбираться на ходу некогда.

- **Приём с аппарата** — денситометр сам отправляет исследование в Orthanc по C-STORE, фронт
  подхватывает задачу опросом `/job/info`. Кнопки загрузки на экране нет. Там же есть проверка
  приёма для установщика: «Ждать снимок» и тестовое исследование с аппарата.
- **Загрузка по кнопке** — лаборант выбирает файл сам. Опрос при этом **выключен**: ждать нечего,
  бекенд не дёргаем.

### Сессия пациента

Станция работает с одним пациентом за раз (`src/lib/station.ts`, `src/context/StationContext.tsx`).

**Снимок приходит только тогда, когда его ждут** — в начале приёма или после «Переснять». Пока
на экране разбор, станция вообще не слушает аппарат, поэтому ничто не может подменить пациента,
который сейчас на столе.

**«Переснять» не отправляет решение на бекенд.** Это переход к следующей попытке: в режиме
аппарата станция снова слушает, в режиме загрузки сразу открывается выбор файла. Попытки копятся
в сессии, со второй окно снимка само делится надвое — кнопка сравнения остаётся, чтобы это можно
было выключить.

**Решение принимается один раз.** Лаборант выбирает попытку — текущую или любую предыдущую.
Выбранная получает `approved` (или `force_approved`, если принята вопреки рекомендации), все
остальные попытки сессии — `rejected` одним запросом. Сессия закрывается, станция ждёт следующего
пациента.

Уйти с экрана с незакрытым посещением нельзя: настройки, выход и перезагрузка спрашивают — принять
последнюю попытку или закрыть посещение без приёма. Посещение, брошенное два часа назад, станция
не возобновляет.

Настройка режима живёт в `localStorage` рабочего места (`src/lib/cabinet.ts`): режим описывает конкретный
денситометр в конкретном кабинете, а не учётную запись — смена меняется, кабинет нет. Ручки для
настроек у бекенда нет.

На том же экране — смена и роль из `GET /user/{id}`, статистика кабинета (считается на клиенте по
загруженной странице очереди) и журнал сбоев и пожеланий с выгрузкой файлом
(`src/lib/journal.ts`).

## Контур разметки

Четыре экрана центра обработки, по которым размеченные снимки превращаются
в более точную модель. Вход — «Разметка» и «Дообучение и подбор параметров»
в боковом меню.

- **Очередь заданий** (`/markup`) — два входа: поток из поликлиник, где в очередь
  попадают снимки, на которых модель сомневается или расходится с таблицей разметки,
  и загрузка своих снимков — с прогоном через модели или без него. Выбор делается
  один раз при загрузке: он решает, что разметчик увидит на экране разметки.
- **Разметка снимка** (`/markup/frame`) — конвейер, а не форма. Открыт один снимок, тот,
  что выдала очередь. В руке одна точка: клик по кости ставит её туда, поставленную можно
  подхватить за маркер и подвинуть, «вернуть как было» возвращает догадку модели. Подсвечена
  мягкой заливкой область **только текущей** точки. Клавиатура ведёт весь цикл: цифры
  переключают точку, пробел — «нет на снимке», `Enter` отправляет снимок и подтягивает
  следующий. Посторонние предметы обводятся руками: цифра выбирает, что обводим, клики
  ставят углы, `Enter` или двойной клик замыкает контур, `Backspace` снимает последний угол,
  `Esc` бросает обводку. Области у предметов нет — обводить можно в любой части снимка.
  Уходит на сервер геометрия: координаты каждой точки в пикселях исходного кадра, «нет на
  снимке», полигоны, вердикт по предметам, особенности и комментарий.
- **Дообучение модели** (`/training`) — список моделей и их статус приходят из разбора снимка
  (`metadata.models`, пять моделей контракта). Модели независимы, обучаются и переключаются
  по отдельности, галочками. В таблице новых версий колонка «Разница» считается арифметикой:
  у каждого показателя записано, в какую сторону он должен двигаться, отсюда знак. Словами
  «лучше» или «хуже» не пишем — выдавать оценку в продукте нечему.
- **Подбор параметров** (`/tuning`) — половина решений анализатора это измеренное число против
  границы. Границу не обучают, её выбирают, и сравнивать не с чем: врач, глядя на сетку
  снимков, и задаёт правило. Экран крутит **настоящие настройки анализатора** — они приходят
  с каждым разбором в `metadata.settings`:

  | настройка | что это |
  |---|---|
  | `trochanter_center_mm` | середина нормы, мм |
  | `trochanter_tol_percent` | допуск вокруг середины |
  | `trochanter_yellow_percent` | сколько ещё за допуском считается сомнением |

  Пять полос считаются из них (`src/lib/settings.ts`): 2,7 ± 63 % даёт норму от 1,0 до 4,4 мм,
  ещё 30 % — полосы сомнения до 0,2 и 5,2. Поэтому бегунки двигаются **парами**: анализатор
  применяет допуск симметрично, односторонней границы у него нет. У середины нормы свой
  бегунок. Сетка — настоящие исследования из очереди: снимок через `GET /dicom/{id}/image`,
  миллиметры и контур измеренной области из `criteria.lesser_trochanter`, клик по плитке
  открывает разбор. Сохранение шлёт `POST /settings` и меняет вердикты: расстояние измерено
  раз, а в какое из трёх состояний оно попадает — решают границы, действующие сейчас.

Фильтр по источнику сквозной: выбранный в очереди, он переезжает на экран разметки,
«следующий» идёт по отфильтрованной очереди и счётчик считает по ней же
(`src/context/AnnotContext.tsx`).

```
src/lib/annotation.ts           состояния точек, правки разметчика, конвейер, очередь
src/lib/settings.ts             настройки анализатора: полосы из них и обратно, модели, кадры
src/lib/tune.ts                 разница между версиями модели
src/services/apiSettings.ts     запись границ: POST /settings, ручки пока нет
src/services/apiAnnotation.ts   очередь и отправка разметки: ручек у бекенда пока нет
src/services/mock/annotStore.ts состояние демо-режима: очередь, дообучение
src/services/mock/annotCases.ts снимки и предсказания моделей — настоящие
src/components/widgets/annot/   четыре экрана
```

Экраны дообучения и подбора параметров работают на настоящем ответе анализатора: список
моделей, настройки и измерения приходят в `metadata` вместе с разбором снимка. Снимки для
экрана разметки выгружает `dicom-analyzer/examples/annotation/export_for_ui.py`
(прогон моделей `qc_prototype` по DICOM из `data/`). Координаты везде — пиксели
исходного кадра, `viewBox` SVG равен кадру, поэтому **миниатюру нельзя обрезать**:
контур уедет с кости.

## Проверка логики без браузера

Браузерных инструментов в проекте нет, поэтому логика гоняется headless: точка
входа собирается esbuild-ом и запускается в Node. `src/checks/annotation.tsx`
проверяет состояния точек, конвейер, очередь, движение границ и распределение
по ним, а затем рисует все четыре экрана в текст и ищет в нём запрещённые слова
из словаря интерфейса.

```bash
node ./node_modules/esbuild/bin/esbuild ./src/checks/annotation.tsx --bundle \
  --platform=node --format=cjs --alias:@=./src --jsx=automatic \
  --loader:.css=empty --define:import.meta.env='{}' \
  --outfile=./node_modules/.cache/annot-checks.cjs
node ./node_modules/.cache/annot-checks.cjs
```

```
  lib/              axios-инстанс, storage, настройки кабинета, журнал, вердикт, критерии

```

## Что зависит от бекенда

Разбор связки и список того, что нужно от `dicom-manager`, — в
`context/system_flows.md` и `context/backend_requests.md`. Коротко:

- выборка по организации неявно по токену — иначе пост поликлиники видит снимки всей сети;
- `study_id` в ответе — без него снимки одного посещения не собрать в группу
  (поле уже лежит у бекендера в таблице `dicom_file`);
- `file_name` и текст ошибки в `JobInfo`;
- порядок `created_at desc` и `total` в очереди;
- `GET /dicom/{id}/image` должен отдавать снимок ровно в размере `metadata.shape` —
  иначе разметка сдвинется относительно анатомии;
- контур разметки: очередь заданий, отправка разметки, сбор для дообучения
  (`src/services/apiAnnotation.ts`) — ручек нет ни одной, цифры сбора пока выдуманные;
- запись настроек анализатора: `POST /settings` (`src/services/apiSettings.ts`). Читаются
  они из `metadata.settings` вместе с разбором, отдельной ручки для чтения не нужно;
- задание очереди должно ссылаться на `job_id`, чтобы снимок и предсказанные точки на экране
  разметки приезжали из `criteria.*`, а не из выгрузки прототипа.

Пока этого нет, группировка, фильтры и статистика считаются на клиенте по загруженной странице.

## Прототип

Исходный HTML-прототип, по которому собран интерфейс, лежит в `prototype/`.
Открывается двойным кликом по `prototype/prototype2.html`, сборка не нужна.

Контур разметки и дообучения — отдельная пара файлов, тоже без сборки:

- `prototype/annotation.html` — очередь заданий, рабочий стол разметчика, экран дообучения;
- `prototype/annotation-lab.html` — выбор оформления холста: раскладка, маркеры, зоны, фон.

Снимки и координаты в них настоящие. Их выгружает
`dicom-analyzer/examples/annotation/export_for_ui.py` (прогон моделей `qc_prototype` по DICOM
из `data/`) в `prototype/annotation.data.js` и `prototype/assets/annot/`. Контракт разметки,
который они показывают, описан в `dicom-analyzer/examples/annotation/README.md`.
