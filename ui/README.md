# Фронтенд контроля качества ДРА

Интерфейс сервиса оценки качества укладки DXA-снимков. Два контура, которые
определяются ролью при входе:

- **Пост рентгенолаборанта** — один экран: вердикт по только что сделанному снимку,
  критерии укладки с пояснениями и решение. Снимок приходит сам, загружать ничего не нужно.
- **Центр обработки** — очередь исследований, карточка снимка с разметкой, пакетная
  обработка архива, отчёты, служебный экран.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Прочие команды: `npm run build` (проверка типов + сборка), `npm run lint`, `npm run preview`.

Нужен Node 20+. Если его нет, подойдёт портативная сборка с nodejs.org — ставить
глобально не обязательно.

## Демо-режим

Хендлеры `dicom-manager` пока возвращают `501`, поэтому интерфейс по умолчанию работает
на демо-данных: `VITE_USE_MOCKS=true` в `.env`.

Подмена живёт в `src/lib/mockAdapter.ts` и работает на уровне транспорта axios, поэтому
**сервисы в `src/services/` настоящие**: чтобы переключиться на живой бекенд, достаточно

```bash
cp .env.example .env
# VITE_USE_MOCKS=false
# VITE_BASE_URL=http://адрес-dicom-manager
```

Ни одна строка в сервисах и хуках при этом не меняется.

Демо-данные собраны из настоящих результатов `qc_prototype/examples`: геометрия разметки
подлинная и точно совпадает со снимками в `public/assets`. Снимки извлечены из
`data/Для теста/*.dcm`, персональные данные в них затёрты организаторами.

## Стек

Vite 7 · React 19 · TypeScript · Tailwind 4 · TanStack Query 5 · react-router-dom 7 ·
react-hook-form + zod 4 · axios · lucide-react.

Соглашения по коду — `context/frontend_style.md`.

## Структура

```
src/
  _auth/            публичная зона: вход
  _root/            приватная зона: layout-ы и страницы
  components/
    ui/             базовые элементы (кнопка, поле, карточка, уведомления)
    shared/         переиспользуемые блоки (окно снимка, разметка, критерии, выбор)
    widgets/        крупные блоки страниц, которые ходят за данными
  context/          авторизация и контур интерфейса
  hooks/            обёртки над react-query
  lib/              axios-инстанс, storage, вердикт, критерии, утилиты
  services/         apiXxx.ts — по одному файлу на сущность
  types/            контракт dicom-manager в типах
  constants/        справочники: русские названия критериев, статусов, решений
```

## Что зависит от бекенда

Разбор связки и список того, что нужно от `dicom-manager`, — в
`context/system_flows.md` и `context/backend_requests.md`. Коротко:

- `study_id` в ответе — без него снимки одного посещения не собрать в группу
  (поле уже лежит у бекендера в таблице `dicom_file`);
- фильтр `GET /job/info?study_id=...`;
- порядок `created_at desc` и `total` в очереди;
- `GET /dicom/{id}/image` должен отдавать снимок ровно в размере `metadata.shape` —
  иначе разметка сдвинется относительно анатомии.

Пока этого нет, группировка и фильтры считаются на клиенте по загруженной странице.

## Прототип

Исходный HTML-прототип, по которому собран интерфейс, лежит в `prototype/`.
Открывается двойным кликом по `prototype/prototype2.html`, сборка не нужна.
